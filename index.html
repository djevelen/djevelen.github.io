CTF 入门 · Misc 签到题

本篇文章旨在让任何人都能享受到在 ctf 赛事中寻找 flag 的乐趣,常言道"hack for fun but not for profit",有时候 flag 里暗藏着不少出题人的小巧思,而找到这些easter eggs(彩蛋),也许就是解出 flag 的一份意外之喜.

读完本文,你将可以:
  • 说清 CTF、flag 和常见解题方向的基本概念
  • 独立解出人生第一道 Misc 签到题,顺便认识 Base64

先认识几个名词

下面这些词汇在下文中不可避免地会出现(令人生厌的),为了您的阅读体验,不妨先简略浏览一番——毕竟有时候欲速则不达(当然,慢工也可能出烂活).

  • ctf:全称为 capture the flag,分为解题赛和攻防赛(本文重点介绍解题赛).选手应该从题目信息和一些提示(hints)里找到所需要的”flag”并提交.提交正确的 flag 即可得分.
  • flag:通俗来说就是题目的答案.通常是一段特定格式的字符串,如 flag{ctf_is_fun!} 等.
  • 解题赛方向:根据题目考点可将 ctf 大致分为:Misc(杂项)、Web(网络安全)、Crypto(密码)、Reverse(逆向工程)、Pwn(二进制漏洞).难度依次递增(是的,你没想错,可怜的 Pwn 手就是要比其他人承受更多).

Base64 是什么

聪明如你一定早就打开了 edge/chrome/firefox 搜索起了 Base64(用百度的朋友建议换一个吧,毕竟一个不小心就点进奇奇怪怪的网站里了).

一句话解释:Base64 是一种编码(encode)手段,目的是把一段明文(大白话)转化为一段密文(鬼话).我们完全可以把编码方法理解为一种函数(实际上在真实程序里就叫函数),明文是自变量,密文是因变量.

惊喜的是,这个函数存在反函数,即每一个因变量有且只有一个对应的自变量,这就说明我们完全可以从密文推出唯一确定的明文.更惊喜的是,在刚刚搜索过程中,你大概率看到了类似”Base64 在线解码网站”之类的提示词.选择那个免费的(比如Base64 编码/解码 - 锤子在线工具),输入密文,选择”utf-8”字符编码,然后点击解码.

为什么能直接还原?Base64 是编码而不是加密:它没有密钥,只是换了一种表示方式,所以任何拿到密文的人都能解码.这正是这道题能成为"签到题"的原因.

第一次尝试

你停住了,要么是看到了一串乱码,要么是看着跳出来的提示词”不是有效字符串,35不是4的倍数”而沉思.

如果你像我第一次做 Misc 题目那样(是的,这是一道 Misc 签到题),脑袋空空如也完全不知所措,别犹豫,复制给 AI,质问它这到底怎么回事,然后在一大段讲解之后,你大概率会直接拿到正确的 flag(但这里我其实并不建议这样做,因为……).

但我相信此时你大概早已有了头绪,你看着”不是4的倍数”,又看了看密文,心想出题人应该不会出一道无法解码的题目,那么关键就在于所给的密文上.

不是4的倍数?那就是输入密文的长度有问题.你心想不可能是输入的密文少了,那只可能是输入的密文多了.

为什么是"4 的倍数"?Base64 按 3 个字节一组编码成 4 个字符,所以有效的 Base64 串长度必须是 4 的倍数(不足的部分用 = 补齐).整段 b"ZmxhZ3…==" 一共 35 个字符,35 ÷ 4 有余数,自然解不了.

发现真相

这时你又看了看密文,突然发现密文里那段 b”……” 似乎略有深意,你回想起了 flag 的格式:flag{……}.

你开始思考会不会 b 对应 flag,” “ 对应 { }?你又开始思考,如果说 flag{……} 这个格式不变,那么我们要找到正确的 flag,实际上只需要解码出花括号里的内容……

赛场上很安静,大家不知怎的键盘都敲得飞快.这次,你将信将疑地只把密文中引号内的内容贴到了解码工具里……

先别急着这步操作,我亲爱的朋友.如果你真的这样做了,你就会看到一个包含了 flag{……} 的完整 flag.

你眉头紧皱,发现事情并不简单.按照我们之前的假设,我们理应只会得到花括号里面的内容.面对这个歪打正着得出来的 flag(当然,它是正确的),真是让人摸不着头脑.

真相:密文 b'ZmxhZ3tpXzFpa2VfeWluZ18wbmx5fQ==' 是 bytes(字节)形式,b"……" 只是该类型值的书写形式,并不是密文的一部分(没错,出题人就是故意这么做的).真正有效的信息只是引号之内的内容,而 **35 减 3 为 32,正好是 4 的倍数**.

以下为闲谈,不感兴趣可以跳过~ 不过话说回来,这题除了 AI 一把梭和用在线解码工具外,其实你也可以自己编写一个脚本来解码(笑).自己写脚本固然痛苦,但确实不可或缺,尤其对于那些禁网禁 AI 的比赛.

思路其实很简洁:对目标字符串用一次 b64decode() 函数即可.有两点需要注意:第一,真正有效的只有引号内的内容,记得先去 b”……” 外壳;第二,Python 3 的 b64decode() 可以直接接收字符串,并不强制要求 byte 类型(真正严格要求 byte 的是 b64encode(),但这里用不到).

样例输出

快速回顾

  • Base64 密文长度必须是 4 的倍数,不足的部分用 = 补齐
  • b”…” 是 Python bytes 类型的书写形式,不是密文的一部分
  • Base64 是编码不是加密,拿到密文就能还原
  • 解码用 base64.b64decode(),它直接接受字符串;b64encode() 才要求 bytes
  • 遇到报错先读报错信息,再回到输入本身找问题

大话数据结构笔记

chapter 1:什么是数据结构

对于基本概念十分了解的朋友建议直接跳到抽象数据类型那里,把基本的格式看一下就可以进入下一篇blog了.对基本概念还不是很了解的朋友建议耐心看完哦~

数据结构是一门研究非数值计算的程序设计问题中的操作对象,以及它们之间关系和操作等的学科

  • 数据:描述客观事物的符号,是计算机中可以操作的对象;
  • 数据元素:组成数据的、有一定意义的基本单位.(可以将数据理解为一个集合);
  • 数据项:数据不可再分的最小单位.但实际讨论问题时,数据元素才是构建数据模型的着眼点
  • 结构:元素之间不是独立的,我们把它们之间的关系就叫做结构.

数据结构又可分为逻辑结构和物理结构

  • 逻辑结构:日常中理解的结构,侧重于描述元素之间的关系.它细分为:

    1. 集合结构(数据元素是平等且无序的);
    2. 线性结构(数据元素一对一);
    3. 树形结构(数据元素有一对多);
    4. 图形结构(数据元素有多对多).

  • 物理结构:数据的逻辑结构在计算机中的存储形式.它细分为:

    1. 顺序存储:元素存储在连续的内存空间中,存储关系可以反映逻辑关系;
    2. 链式存储:元素随意存储在内存空间中(可以连续也可以不连续),位置关系不能反映逻辑关系,必须引入指针.

抽象数据类型 :

一个具体的数学模型和对应的操作.我们完全可以从实际问题出发,做出最简单的归纳,而不用先去考虑如何用计算机去实现(实际上就算是从抽象的本质).这是一个很小却很重要的点.

前言(牢骚)

  • 实际上最开始学数据结构时我也不理解为什么要引入算法,甚至得出了学校数据结构课像杂种的结论.但现在来看想要搞清楚数据结构的几种类型确实很容易,但是想要真正理解它们的用处是离不开算法的.算法也许才是数据结构的精髓和难点.所以请对此不熟悉的朋友们耐心读完这一篇文章,希望你会有所收获.

算法是解决具体问题的求解步骤,在计算机中表现为指令的有限序列

  • 算法的五个特性:
    1. 输入和输出;
    2. 有穷性(有限步骤里完成);
    3. 确定性(每个步骤不会产生二义性);
    4. 可行性(也许可以粗鄙地理解为正确性,前者针对过程,后者针对结果);
  • 算法效率的度量方法:事后统计法(顾名思义就是在计算机上老老实实跑一遍代码)和事前分析估算法(喜闻乐见的时间复杂度和空间复杂度);
  • 函数的渐近增长:对于函数$f(n)$和$g(n)$,很难笼统地说哪个的值一定更大,n在不同范围时结果一般不同(求临界值解个不等式就行了).然而当n足够大时,两个函数谁更大却是确定的,我们说更大的函数渐近增长更快.
    • 实际上就是无穷大量比阶的问题(n取正数且足够大),我们完全可以忽略常数,不论它是单独的一项还是系数,因为不影响最终结果(同阶除外).这也是时间复杂度化简的理论基础.

时间复杂度的求解本质就是计算目标代码所有语句执行次数总和的最高阶

    $O(1) < O(logn)<O(n)<O(nlogn)<O(n^2)<O(n^3)<O(2^n)<O(n!)<O(n^n)$

  • 最坏情况:对于n个元素,最后一次(花了n次)才找到目标对象.最坏情况运行时间是一种保障.除非特定规定,不然一般提到的运行时间都是最坏情况运行时间.

  • 平均情况:对于n个元素,花了$\dfrac {\rm n}{2}$次就找到了目标对象.平均运行时间是所有情况中最有意义的,因为它是期望的运行时间.

用空间换时间

  • 空间复杂度:通过计算算法所需要的存储空间实现,其计算公式记作:$S(n) = O(f(n))$,n为问题的规模,$f(n)$是问题所占据存储空间的函数.
  • 若算法执行时所需要的辅助空间相对于输入数据量而言是个常量,则称此算法为原地工作,空间复杂度为$O(1)$.
  • 复杂度前无限定词时,默认指时间复杂度.

线性表是零个或多个数据元素的有限序列

  • 线性表的数学定义:若将线性表记作$(a_1,……a_{i-1},a_i,a_{i+1}……,a_n)$,则表中$a_{i-1}$领先于$a_i$,$a_i$领先于$a_{i+1}$,则称$a_{i-1}$是$a_i$的直接前驱元素,$a_{i+1}$是$a_i$的直接后继元素.除了表头和表尾,线性表中其他元素均只有一个前驱和后继元素.

  • 线性表元素的个数$\rm n$定义为线性表的长度.$\rm n$为$0$时,称为空表.

  • 线性表有顺序,强调一一对应,元素有限
